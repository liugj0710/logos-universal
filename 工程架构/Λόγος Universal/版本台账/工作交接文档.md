## 三、关键设计决策（防幻觉必读）

### 3.1 为什么 Bing 和百度要拆分成独立文件？

**Bing 反爬机制特殊**：
- Bing 检测的是"访问模式"，不是浏览器指纹
- 直接访问 `bing.com/search?q=xxx` → 返回反爬干扰页（"新的意思"、"新闻首页"）
- 必须模拟真实用户：打开首页 → 搜索框输入 → 点击搜索 → 结果页
- 因此必须用 DrissionPage 浏览器自动化

**百度反爬宽松**：
- requests 即可稳定获取真实结果
- 无需浏览器开销

**拆分后优势**：
- 后续维护者优化 Bing 时不会误伤百度
- 后续维护者优化百度时不会误伤 Bing

### 3.2 为什么用 DrissionPage 而不是 Selenium/Playwright？

- DrissionPage 基于 CDP 协议，**默认隐藏 `navigator.webdriver`**
- 无需额外反检测配置（Selenium 需要 `undetected-chromedriver`，Playwright 需要 `stealth` 插件）
- 国内社区活跃，中文文档完善
- 用户已有 DrissionPage 使用经验（BOSS 直聘爬虫案例）

### 3.3 浏览器为什么用无头模式？

- 有头模式会弹出浏览器窗口，不适合服务器长期运行
- 无头模式 + 正确 UA 设置后，Bing 无法检测
- **注意**：UA 必须包含 `Chrome/xxx` 而非 `HeadlessChrome`，否则 Cloudflare 类检测会拦截

### 3.4 内容过滤为什么是 200 字？

- Bing 二次爬虫失败时会 fallback 到 snippet
- snippet 通常只有几十到一百字，内容质量极低
- 200 字阈值可以彻底阻断这类垃圾，防止 Agent 误判"资料不足"
- 如果后续发现过滤过于严格，可以调整为 150 字

### 3.5 模型名为什么是 `deepseek-v4-flash`？

- 设计文档 v0.2.1 明确要求使用 DeepSeek-V4 Flash
- 原代码写的是 `deepseek-chat`（V3），已统一修正
- 如果 DeepSeek 更新模型名，需同步修改 `planner.py` 和 `rewrite.py`

## 五、已知问题与注意事项

### 5.1 已知问题

| 问题 | 影响 | 处理建议 |
|------|------|----------|
| 二次爬虫偶尔超时（8s） | 该结果 fallback 到 snippet | 正常现象，不影响整体质量 |
| SSL 握手失败（部分政府网站） | 该结果内容为空 | 正常现象，不影响整体质量 |
| 浏览器首次启动约 2-3 秒 | 首次搜索延迟稍高 | 单例复用，后续搜索无延迟 |

### 5.2 注意事项

1. **不要尝试用 requests 替代 DrissionPage 做 Bing 搜索**：已反复验证不可行
2. **不要修改 search_bing.py 的交互逻辑**：首页→搜索框→点击搜索 这个顺序是反爬关键
3. **不要随意降低内容过滤阈值**：<200 字过滤是 P0 修复的核心，降低会导致垃圾内容回流
4. **替换 Dify 提示词前备份原提示词**：防止新提示词有问题时可以回滚
